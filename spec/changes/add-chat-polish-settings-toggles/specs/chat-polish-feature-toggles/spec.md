# chat-polish-feature-toggles

对话区打磨插件的设置页独立开关能力：dsh web 官方设置页出现本插件分区菜单，6 个功能各带独立开关；开关状态 localStorage 持久化；切换即时生效；关闭某功能 = 该功能回退官方原生形态。

界面真相源约定：本能力的设置分区 UI 无界面原型；分区结构、开关行形态以官方设置页既有分区（模型/内置插件等）与仓内先例 `fenix-dsh-auth`「登录」分区的同构形态为准。

## ADDED Requirements

### Requirement: 设置分区菜单

插件 MUST 在 dsh web 官方设置页注册一个独立分区（label「对话区打磨」），经官方 keyed 插槽 `settings.section` 与 `settings.section.icon` 注册（order 取既有分区最大 order+1 的尾随探测，先例 `fenix-dsh-auth/client.js`）；分区面板 MUST 渲染 6 个功能行，每行含功能名称与开关控件。

#### Scenario: 分区可见且可达
- **WHEN** 用户打开 dsh web 设置页
- **THEN** 分区导航中出现「对话区打磨」条目（带图标，位于既有分区之后），点击进入后可见 6 个功能行，每行有功能说明文案与开关控件

#### Scenario: 默认全开
- **WHEN** localStorage 中不存在本插件的开关持久化键（首次使用/清理过存储）
- **THEN** 6 个功能行开关全部呈开启态，插件行为与本能力上线前的 v0.2.2 行为一致

#### Scenario: 插槽失配降级
- **WHEN** dsh 升级致 `settings.section` 槽结构/契约漂移，分区注册失配
- **THEN** 仅设置分区菜单缺席（console 留降级告警），6 个功能的默认行为不受影响、不出现页面报错

### Requirement: 六功能独立开关与即时生效

6 个功能 MUST 各自拥有独立开关，互不影响：①对话列留白 24px（含列宽把手隐藏、回到底部浮钮对齐、hero 空会话栈铺满同一 24px 基线）②滚动条样式 ③输入框 80% 宽度居中（提示条/队列坞同轴）④用户消息 Markdown 渲染 ⑤hero 工作区行对齐输入卡 ⑥输入框 ↑/↓ 历史导航。任一开关切换 MUST 即时生效（无需刷新页面），关闭 = 该功能回退官方原生形态，开启 = 恢复插件形态。

#### Scenario: 关闭留白即时回退
- **WHEN** 在对话页已渲染的状态下关闭「对话列留白 24px」开关
- **THEN** 无需刷新，消息列即时回退官方居中布局（920px 上限恢复）、列宽把手重新可见；重新开启后即时恢复 24px 铺满形态；其余 5 个功能行为不变

#### Scenario: 关闭 Markdown 渲染回退纯文本
- **WHEN** 关闭「用户消息 Markdown 渲染」开关
- **THEN** 既有与后续用户消息气泡即时回退官方等效的纯文本投影形态（附件/图片卡行为不变）；重新开启后恢复 Markdown 渲染（标题/列表/代码高亮）

#### Scenario: 关闭历史导航不伤输入
- **WHEN** 关闭「输入框 ↑/↓ 历史导航」开关后在输入框按 ↑/↓
- **THEN** 不召回已发送消息，光标按官方行为在多行文本间移动，输入框编辑/发送/IME 组合完全正常；重新开启后召回行为恢复

#### Scenario: 关闭视觉类功能逐一回退
- **WHEN** 分别关闭「滚动条样式」「输入框 80% 宽度居中」「hero 工作区行对齐」开关
- **THEN** 各自即时回退官方对应形态（dsh 自绘滚动条、920px/官方宽度轴、hero 行官方边距），其余功能互不影响

#### Scenario: 全部关闭等于官方原生
- **WHEN** 6 个开关全部关闭
- **THEN** 对话区呈现官方原生形态（嵌入形态豁免除外），无插件残留样式与行为，控制台无未处理异常

### Requirement: 开关状态持久化与降级

开关状态 MUST 经 localStorage 持久化（键名形如 `fenix-chat-polish.toggles`，JSON 对象 `{功能ID: bool}`，仅记录非默认值或缺省即开启由实现取其一并全站一致）；持久化值 MUST 在页面刷新、浏览器重启后保持。存储值损坏（非 JSON/未知功能键）MUST 忽略损坏部分回退开启态；localStorage 不可用（隐私模式/配额）MUST 降级为会话内生效且不抛未处理异常。

#### Scenario: 刷新后状态保持
- **WHEN** 关闭任意 2 个功能后刷新页面（或重开浏览器）再打开设置分区
- **THEN** 这 2 个功能仍呈关闭态且行为仍关闭，其余 4 个仍开启

#### Scenario: 损坏数据回退
- **WHEN** 手动将持久化键改写为非法 JSON（或含未知功能键的对象）后加载页面
- **THEN** 页面正常加载，损坏值被忽略、按全开处理，不抛未处理异常

#### Scenario: 存储不可用降级
- **WHEN** localStorage 读写抛异常（隐私模式模拟）时切换开关
- **THEN** 开关在当前会话内即时生效，控制台仅留降级告警，无未处理异常；刷新后回默认全开

### Requirement: 嵌入形态豁免不受开关影响

fenixd dashboard 嵌入形态（root 带 `.embeddedBody`）MUST 维持整体验免——无论开关状态如何，嵌入形态下插件不注入任何样式与行为改动。

#### Scenario: 嵌入形态恒豁免
- **WHEN** 在嵌入形态下（任意开关组合，含全开）
- **THEN** 对话区保持官方自身宽度轴与形态，插件 CSS 与行为不生效
