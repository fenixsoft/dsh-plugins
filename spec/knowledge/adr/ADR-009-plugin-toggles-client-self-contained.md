# ADR-009：插件功能开关 client 半自持，插槽注册常驻内部分流

date: 2026-11-24
status: accepted

## Context

插件为各自功能提供用户级开关/偏好时，持久化与条件化有两种走向：依赖宿主 dsh web 的 settings 写入面，或插件 client 半自持。宿主 settings 写入面在非 loopback 访问下整体不可用（知识域 plugin-rollout 实证），且依赖宿主写路径与插件零构建、纯浏览器侧的形态相悖。同时，功能条件化若采用运行时动态注销/重注册 keyed 插槽，宿主 inject 回调生命周期契约未经验证，abdicate 兜底语义会混淆「失败」与「主动关闭」。

## Decision

插件功能开关一律 client 半自持：localStorage 单键 JSON（只记录非默认值，缺省即默认）+ 模块级 pub/sub store 作为唯一条件化读源；不向宿主 settings 引入任何插件写路径。功能条件化一律采用「注册常驻 + 组件/处理器内部按 store 分流」：keyed 插槽注册与文档级监听保持挂载不做运行时注销，关闭态由入口布尔短路放行；样式类功能以单 style 标签 `textContent` 按开启集合同步重建。

## Consequences

- 插件开关在宿主 settings 不可用场景（非 loopback 访问）下照常工作；持久化降级（存储损坏/不可用）在插件内闭环处理，不牵连宿主。
- 宿主升级致插槽契约漂移时，降级面收敛为「开关 UI 缺席」，功能本体与持久化键不受影响；但插槽遮蔽注册常驻意味着关闭态功能仍保留最小挂载开销（布尔读级别，可忽略）。
- 后续插件新增用户级开关/偏好 MUST 沿用本裁定，不再为单插件重新选型持久化与条件化机制。
